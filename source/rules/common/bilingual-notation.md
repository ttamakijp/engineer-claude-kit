# 英語混じり時の日本語併記

## 要件

英語表現を使う場合、初出時に日本語訳を括弧で併記する。例: `audit (監査)`、
`scope (対象範囲)`、`dangling 参照 (未起票の参照)`。

## Do

- 同一文書内の 2 回目以降は併記省略可
- 迷ったら併記する (過剰でも読者に親切)
- 訳語は文脈に応じて選ぶ (用語集は作らない、固定訳の強制はしない)

## Don't

- 業界標準の純粋技術用語 (git / GitHub / README / JSON / YAML / ADR / Bedrock / Sonnet / Haiku 等) に併記しない
- 英語表現を併記なしで多用しない (読者の理解負荷が高まる)
- 文脈に合わない無理矢理な訳語を併記しない (むしろ理解を妨げる)

## 例外

適用対象は user 向け応答、markdown ドキュメント、コミットメッセージ本文。以下は適用外:

- ASCII only 制約のある PowerShell スクリプト (英語のみ可)
- コードブロック内のコード / コマンド / 出力例
- 既存外部 API / プロトコル名 (例: `OAuth` `HTTPS`)
- コミット subject の英語 (Conventional Commits の要件が優先)
